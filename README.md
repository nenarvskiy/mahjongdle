# RNGlDle Mahjong

Ежедневная игра по маджонгу в браузере: раздаётся рука из 14 тайлов, игрок
выбирает **один сброс**, и оставшиеся 13 тайлов оцениваются по системе очков
v4: **база (состояние × тир) + структуры + плоские яку**. Тир задаётся ханами
лучшей достижимой руки (фу не считаются, манган = 5+ хан, цумо хана не даёт,
дора, ура-дора и ака-дора дают хан, но не отдельными очками; ура-доры
открываются после сброса и в выборе сброса не участвуют). Если 14 тайлов сразу
собираются в готовую руку — она оценивается по строке «Готовая рука» своего
тира (строка = 2× строки «Тенпай»: готовая рука — гарантированный тир без
сброса и без риска).

Всё на «чистом» браузерном ESM: ни сборщика, ни зависимостей. Нужен статический
сервер (ESM-модули не грузятся с `file://`) — например `npx serve .` или
`py -m http.server`, дальше открыть выданный адрес.

## Где лежат числа

Все очки, пороги и правила — в **`config/scoring.json`**. В коде чисел стоимости нет.

* `systems.v4` — система очков проекта, единственный источник для **и игры, и
  статистики**: плоская таблица базы состояние × тир (4×6, последняя строка —
  «Готовая рука»), плоские цены 13 структур и 20 яку (включая джекпоты: большие ветра 23·10¹², только терминалы/зелёные 150·10⁹, малые ветра 100·10⁹, только хоноры 10·10⁹, большие драконы 3·10⁹, рянпейко 770·10⁶),
  пороги тиров (манган = 5+ хан), правила (фу нет, цумо нет, риичи +`riichiHan`,
  дора от индикатора, ура-дора — открывается после сброса и входит только в
  финальный счёт, ака-дора (одна красная пятёрка на масть), flat-бонуса за
  готовую руку нет). Читается `src/config.js` (игра) и
  `stats/scorestat.py` (статистика).
* `legacyGame` — мёртвая наследованная модель (множители, фу); ни игра, ни
  статистика её не читают. Оставлена только как исторический архив.

Правка `config/scoring.json` не требует трогать код. После правки:

```powershell
node --test                              # игра: тесты + оба паритета должны пройти
node --test test/v4-parity.test.js       # паритет игра <-> статистика (169 рук)
node --test test/v4-complete-parity.test.js  # паритет готовых рук (622 руки)
py stats/scorestat.py -n 20000 --quick   # статистика: отчёт на 20k рук
py stats/scorestat.py --mode complete -n 20000000 --quick  # режим 2: готовые руки
py stats/scorestat.py --mode yaku -n 20000000 --quick      # только яку, без шантенов (быстро)
```

`src/` и `config/` связаны через JSON-импорт
(`import cfg from '../config/scoring.json' with { type: 'json' }`) — нужен
Node 22+ и браузер с поддержкой import attributes (Chrome/Edge 123+,
Firefox 138+, Safari 17.5+). Очки структур дополнительно правятся в браузере
через диалог «Стоимость структур» (сохраняются в localStorage поверх конфига;
кнопка «Вернуть стандартные значения» возвращает числа из конфига).

## Вход через Google и таблица дня

Игра остаётся статической; опциональный сервер `server/` добавляет вход через
Google (Google Identity Services, без редиректов) и **таблицу дня**: каждый
игрок раз в день генерирует «руку дня» (кнопка «Сгенерировать руку»; до
нажатия — 14 тайлов рубашкой вверх, после — анимация переворота 4/4/4/2,
кнопка блокируется до следующего дня, рука закрепляется в браузере)
и собирает результат, сервер хранит лучший, публичный топ-10 виден всем.

* `src/auth.js` — кнопка Google (GIS ID-токен), сессия в localStorage,
  запросы к API; `src/leaderboard.js` — панель топ-10.
* `config/auth.json` — `googleClientId` + `apiBaseUrl`. Пока `googleClientId`
  пустой, функция **выключена**: кнопки нет, игра работает как раньше.
* `server/` — Express + `google-auth-library` + встроенный `node:sqlite`
  (Node 24+): `POST /api/auth/login` (проверка ID-токена), `GET /api/me`,
  `POST /api/scores` (лучший на день), `GET /api/scores/:date` (публичный топ).
  Сервер раздаёт и саму игру (один origin, один порт, `STATIC_DIR` — каталог
  фронтенда, по умолчанию корень репозитория) — поэтому хостинг возможен на
  одной машине без домена (Tailscale Funnel). Тесты:
  `node --test test/server.test.js`.
* **Роли** (admin / test / player, по умолчанию player): списки email — в
  `server/config/roles.json` (hot-reload, без рестарта) или в игре кнопкой
  «Роли (admin)». **test** и **admin** получают «Тестовый режим»
  (`src/test-mode.js`): неограниченные руки + ручные руки 13/14 тайлов,
  очки считаются как в игре (те же `evaluateHand`/`evaluateCompleteHand`),
  но **ничего** отсюда не попадает в таблицу, статистику и будущие
  достижения. `admin` — ещё и панель управления ролями.
* **Сквозной лог** (`src/event-log.js` → `POST /api/events`): **один блок =
  одна посчитанная рука** — рука, условия и счёт с полной разбивкой «что за
  что»; жалоба из тестового режима прикладывается к тому же блоку
  (`payload.report`). Несчитанные руки (только сгенерированные) в лог не
  пишутся; пересчёт при смене условий/другом сбросе обновляет тот же блок.
  Админ видит всё кнопкой «Логи и жалобы» (`src/bug-viewer.js`): вкладки
  «Жалобы» и «Все руки», каждая карточка — рука тайлами, счёт с разбивкой,
  условия и текст жалобы (если есть).

Запуск и деплой (Google Cloud Console, авторизованные origin-ы, `STATIC_DIR`,
Tailscale Funnel без домена, Render/VPS/Docker, настройка `config/auth.json`) —
пошагово в [server/README.md](server/README.md).

## Статистика системы v4

`stats/scorestat.py` считает миллионы рук с идеальным сбросом на системе v4:
распределение счёта, очки и количества по каждой ячейке базы/структуре/яку
и сравнение с частоты́ми дизайна. Подробности, результаты прогона и набор
проверок (паритет игра ↔ статистика, разбиение Python ↔ JS, шантен, профиль
ядер) — в [stats/README.md](stats/README.md).

## Статус перехода на v4

Переход завершён: игра (`src/`) и статистика (`stats/`) работают на одной
системе — `systems.v4` из `config/scoring.json`. В v4 нет фу и множителей:
итог = база (состояние × тир) + структуры + плоские яку, тир — по хану
(манган = 5+ хан, Якуман = 13+). Дора, ака-дора, риичи и пинфу дают хан, но
не добавляют отдельных очков. Цумо хана не даёт. Ура-доры берутся из мёртвой
стены и открываются после сброса, поэтому в решение (выбор сброса, тир,
структуры, яку) они не входят, а в финальный хан и очки входят; якуман
урадоры (как и дору) не получает. Готовая 14-тайловая рука оценивается по
строке «Готовая рука» своего тира (2× строки «Тенпай»). Совпадение двух
реализаций контролируют паритетные тесты `test/v4-parity.test.js` (169 рук,
эталон из `stats/tools/gen_v4_reference.py`) и
`test/v4-complete-parity.test.js` (622 готовые руки, эталон из
`stats/tools/gen_complete_reference.py`). Старая модель сохранена в конфиге
как `legacyGame` и не используется.
