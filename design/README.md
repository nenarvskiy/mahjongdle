# Проектирование системы v4

Материалы, из которых выросла система очков v4, плюс референсные данные, с
которыми сравнивается симуляция. Код игры (`src/`) и статистика (`stats/`)
этот каталог не импортируют.

* **`scoring-v4.md`** — итоговое описание системы v4: устройство (база × тир,
  плоские структуры, плоские яку), вывод цен из часто́т (1 блок ≈ 13.727 EV),
  финальные таблицы и замечания по сходимости с симуляцией.
* **`mahahaahhaah.py`** — программа-первоисточник (режим `yaku` и режим `shanten`):
  перебор победных рук, достижимых за минимальный добор, и подсчёт хана.
  Ядра `analyze`/`eval_regular` из неё перенесены в `stats/scorestat.py` как есть
  (поэтому статистика и дизайн считают тир одинаково).
* **`maj_stat.txt`** — отчёт исторического прогона 500M рук: частоты состояний и
  ячеек базы (14 тайлов, лучший сброс по шантену). Правила того прогона — ДО
  финальных (цумо давало хан, урадор не было), поэтому как «дизайновая» частота
  базы в `config/scoring.json` (`systems.v4.designFrequencies.base`) он больше не
  используется: база перемерена 2026-10-17 своими же ядрами статистики
  (`py stats/scorestat.py --mode design` / `--mode design-complete`) под финальные
  правила — см. раздел «Пересчёт 2026-10-17» в `scoring-v4.md`. Файл оставлен
  как источник исходных ча́стот и как объяснение прежних цен.

## `tools/` — как считались частоты

| файл | что делает |
|---|---|
| `exact_probs.py` | точные вероятности событий в случайной 14-тайловой руке (комбинаторика, вес `C(4,c)`) |
| `struct_probs.py` | точные вероятности структур/событий для 13 и 14 тайлов |
| `verify14.py` | точные 14-тайловые вероятности всех событий режима `yaku`, кросс-чек симуляции |
| `check_rare.py` | перепроверка редких событий против 5B-симуляции |
| `check_z.py` | z-проверка 5B-симуляции против точных вероятностей (`|z|>3` — подозрение) |
| `simulate.js` | симуляция событий на 14 тайлах (использует код проекта из `src/`) |
| `simulate13.js` | то же на 13 тайлах после лучшего сброса по шантену |

Запуск: `py design/tools/<файл>.py` и
`node design/tools/simulate.js` (`SAMPLES=...` через переменную окружения).
Это исторические инструменты: они писались до появления `config/scoring.json`
и содержат числа внутри себя.
